- Core idea: Treat images as sequences of tokens, just like text tokens in a Transformer, and feed them into the same or a closely related auto-regressive model that is already familiar from language modeling.

What changes when images are tokens

- Tokenization of images:
  - Instead of words, the image is broken into a grid of visual tokens (patchlets or regions). Each patch is mapped to a discrete token via an image tokenizer (learned or discrete VQ-style codebook).
  - You now have two streams of tokens: text tokens and image tokens, forming a single joint sequence for the model to process.

- Embeddings and input representation:
  - Text tokens use standard wordpiece/embedding vectors plus positional encodings.
  - Image tokens also have embeddings (image-token embeddings) plus their own positional encodings corresponding to the patch location in the image.
  - There is no separate image encoder in the front end; instead, the image tokens are embedded and fed into the transformer as part of the same sequence.

- Model architecture (shared backbone, modality integration):
  - The backbone remains a Transformer (self-attention + feed-forward layers). The same layers process both text tokens and image tokens.
  - Modality fusion is achieved by concatenating text-token embeddings and image-token embeddings into one sequence, with learned type/positional cues to help the model distinguish modalities if needed.
  - Optional: a light conditioning or cross-attention mechanism may be used to align text prompts with image token contexts, but the core is a single shared Transformer.

- Generation and conditioning flow:
  - Pretraining: The model learns from mixed-modality data (text, and image tokens extracted by the image tokenizer) to predict the next token in the joint sequence.
  - Inference/generation: Given a text prompt (and optionally a starting image prompt), the model autoregressively generates the next tokens, which could be text tokens or image tokens depending on the prompt and the desired output.
  - Special handling: To output images, image tokens are decoded back into pixel blocks by the image decoder (the Image De-Tokenizer) after generation.

- Output heads and decoding:
  - Text outputs use a standard language-model head (vocabulary logits) to generate next text token.
  - Image outputs use a separate image decoder or de-tokenizer that maps predicted image tokens back to image patches, reconstructing the final image.
  - In some variants, a unified decoding head can produce either text or image tokens depending on the generation path.

- Training signals and objectives:
  - The objective is often a unified cross-entropy over the joint token sequence (text tokens and image tokens), training the model to predict the next token regardless of modality.
  - Additionally, alignment losses or cross-modal consistency losses can be used to improve coherence between generated text and the corresponding image content.

- Practical implications for a student:
  - The main difference is that the input image is converted into a sequence of discrete tokens and treated as another set of tokens alongside text, all processed by a single Transformer.
  - You still use positional information, but for images you encode 2D patch locations as part of the token position.
  - The model learns to generate either text or image tokens autoregressively, enabling cross-modal generation (e.g., “Here is a recipe for banana bread.” text output plus a corresponding image output).
  - The separation into “image tokenizer” and “image de-tokenizer” is analogous to a vocabulary and a decoder for pixels, but everything else remains Transformer-based.
